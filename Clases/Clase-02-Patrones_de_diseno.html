01

No reinventar la rueda

Un patrón de interfaz es una solución ya validada a un problema de interacción recurrente. Ignorarlo sin una razón fuerte no es creatividad — es fricción evitable, tanto para quien lo construye como para quien lo usa.

El martes vimos consistencia como principio. Los patrones de hoy son consistencia aplicada a escala: miles de productos ya resolvieron "cómo se ve un alert", "cómo se agrupa un menú", "cómo confirma alguien una acción destructiva" — y las respuestas convergieron porque le funcionan a la gente, no por moda.

La idea: la rueda cuadrada "funciona" — llega, técnicamente — pero cada vuelta cuesta esfuerzo extra que nadie pidió. Un patrón conocido no es menos creativo; es la fricción que otros ya resolvieron antes.

02

Alertas

Muestran información importante y breve de forma que llame la atención sin interrumpir el trabajo del usuario — a diferencia de un dialog, no bloquean nada.

Los lectores de pantalla las detectan automáticamente cuando se renderizan dinámicamente — algunos sistemas operativos incluso generan sonido. No deben robar el foco del teclado y, salvo casos puntuales, no deberían desaparecer solas.

El contenedor lleva role="alert". Usos típicos: errores, precauciones, mensajes de éxito, información nueva.

01

Alert de error

✕ Evitar
Error al guardar los cambios.
se confunde con texto normal
✓ Preferir
⚠
No se pudo guardarRevisa tu conexión e intenta de nuevo.
✓

Principio: feedback — el usuario no debería tener que leer con atención para notar que algo falló. Color, ícono y jerarquía tipográfica hacen ese trabajo antes que el texto.

HTML
<div role="alert"> <span aria-hidden="true">&#9888;</span> <strong>No se pudo guardar</strong> <span>Revisa tu conexión e intenta de nuevo.</span> </div>
03

Botones

En una pantalla con varias acciones, no todas pesan igual — el botón tiene que decirlo antes de que alguien lea las etiquetas.

01

Jerarquía de acciones

✕ Evitar
las tres compiten por atención
✓ Preferir
✓

Principio: jerarquía y affordance — un botón lleno se ve más "clickeable" y más importante que uno de borde, que a su vez pesa más que un link de texto. La forma anticipa la acción antes de leerla.

HTML
<button type="button">Guardar</button> <button type="button">Cancelar</button> <button type="button">Ver ayuda</button> <!-- toggle --> <button type="button" aria-pressed="false">Fijar</button> <!-- menú --> <button type="button" aria-haspopup="true" aria-expanded="false"> Opciones </button>

Más allá de la jerarquía visual, un botón cumple uno de tres roles funcionales — y cada uno pide su propio atributo ARIA:

Genérico
Ejecuta una acción — type="button" tabindex="0"
Toggle
Alterna estado on/off — aria-pressed="true|false", anunciado por el lector de pantalla
Menú
Abre una lista de opciones — aria-haspopup="true" aria-expanded="false"
04

Links

Funcionan como referencia interactiva a un recurso — interno (dentro de la misma página) o externo (otra página). Tienen cuatro estados que el CSS puede estilar por separado.

Los cuatro son links reales — :visited, :hover y :active están forzados por clase para mostrar los cuatro estados a la vez, porque el navegador no deja simular :visited ni :active sin que el usuario los dispare.

Normal Hovered Visitado ↗ Activo
CSS
a:link { color: var(--brand); } a:visited { color: var(--ink-faint); } a:hover { background: var(--brand-bg); } a:active { background: var(--brand); color: var(--paper); }
01

Link vs. Botón — cuándo usar cada uno

<a> — Link

  • Navega a otra página o sección
  • Se activa con Enter
  • Puede abrirse en nueva pestaña
  • Tiene estados :visited, :hover
  • Ej.: ir a la página de contacto

<button> — Botón

  • Ejecuta una acción en la página
  • Se activa con Enter o Espacio
  • No cambia la URL
  • No tiene estado :visited
  • Ej.: guardar formulario, abrir modal

Principio: consistencia semántica — usar <a> para navegación y <button> para acciones no es un detalle técnico, es lo que hace que teclado y lector de pantalla se comporten como el usuario espera.

HTML
<!-- Navega: URL cambia, :visited aplica --> <a href="/contacto">Ir a contacto</a> <!-- Ejecuta una acción: no cambia la URL --> <button type="button">Guardar formulario</button>
05

Checkboxes

El área que se puede tocar tiene que ser tan grande como lo que se lee — no solo la cajita.

La WAI reconoce dos variantes: de dos estados (seleccionado / no seleccionado) y de tres estados (seleccionado / parcialmente seleccionado / no seleccionado) — este último es el típico "seleccionar todo" cuando solo algunos hijos están marcados.

01

Área de click

✕ Evitar
Acepto los términos y condiciones del servicio
el texto no es parte del control
✓ Preferir
✓

Principio: affordance — un `<label>` envolviendo el input hace que todo el bloque sea clickeable, no solo un cuadradito de 12px. Regla de Fitts: objetivos más grandes son más rápidos y fáciles de acertar.

HTML
<label> <input type="checkbox" checked> <span>Acepto los términos y condiciones</span> </label> <!-- 3 estados: "mixed" no existe como atributo HTML --> <input type="checkbox" id="select-all"> <script> document.getElementById('select-all').indeterminate = true; </script>
06

Dialogs (Modals)

Interrumpen a propósito — por eso cuestan la atención completa del usuario. Un dialog denso desperdicia esa interrupción.

Es una ventana superpuesta a la pantalla principal (o a otro modal). El contenido fuera del modal generalmente se oscurece con un overlay, y el usuario no puede interactuar con él hasta cerrarlo.

01

Confirmación de acción destructiva

✕ Evitar
¡Atención!
Esta acción afecta varios elementos relacionados y puede tener consecuencias que no se pueden revertir fácilmente.
4 botones iguales, sin foco
✓ Preferir
Eliminar componente
Esta acción no se puede deshacer.
✓

Principio: jerarquía — una acción irreversible necesita una sola pregunta clara y dos salidas, no cuatro caminos. El color de la acción destructiva anticipa la consecuencia antes del click.

Con el dialog abierto, el teclado se mueve solo entre lo que hay dentro de él — nunca debería "escaparse" hacia el resto de la página:

Tab
Avanza al siguiente elemento enfocable; en el último, vuelve al primero
Shift + Tab
Retrocede al anterior; en el primero, vuelve al último
Esc
Cierra el modal

Es un <dialog> real — prueben Tab, Shift+Tab y Esc con el modal abierto.

Editar perfil
HTML
<dialog aria-labelledby="dialog-title"> <form method="dialog"> <h2 id="dialog-title">Editar perfil</h2> <button type="button" aria-label="Cerrar">&#10005;</button> <label> <span>Nombre</span> <input type="text" name="nombre"> </label> <label> <input type="checkbox" name="notificaciones"> <span>Recibir notificaciones por correo</span> </label> <button type="button" id="cancelar">Cancelar</button> <button type="submit">Guardar</button> </form> </dialog> <script> // showModal() da foco atrapado + Esc + backdrop nativos — // nada de esto está reimplementado a mano. dialogEl.showModal(); </script>
02

ARIA manual vs. <dialog> nativo

ARIA manual (tradicional)

  • role="dialog" aria-modal="true"
  • Focus trap implementado a mano en JS
  • Esc y backdrop-click a implementar
  • Control total, más código para mantener

Nativo <dialog> (moderno)

  • dialog.showModal()
  • Esc-to-close y backdrop incluidos gratis
  • Focus trap manejado por el navegador
  • Recomendado en navegadores modernos
HTML
<!-- ARIA manual --> <div role="dialog" aria-modal="true" aria-labelledby="t"> <h2 id="t">Título</h2> <!-- focus trap, Esc y backdrop-click: a implementar en JS --> </div> <!-- Nativo --> <dialog aria-labelledby="t"> <h2 id="t">Título</h2> </dialog> <script>dialogEl.showModal();</script>
07

Menús

Una lista plana de doce opciones no es un menú organizado — es una lista larga que hay que leer entera.

Muestra opciones relacionadas de forma temporal, y aparece al interactuar con un botón, tab u otro control. Al elegir una opción, el menú se cierra. El foco de cada ítem se maneja con JS — no es gratis como en un link.

Anatomía
Menu control (lo que abre) → Menu (contenedor) → Menu item (cada opción, con ícono + label)
Esc
Cierra el menú y devuelve el foco al control que lo abrió
01

Agrupación por sección

✕ Evitar
todo pesa igual
✓ Preferir

Archivo

Cuenta

✓

Principio: jerarquía y consistencia — agrupar por función reduce la carga cognitiva de escanear la lista. Un divisor y una etiqueta cuestan poco y ahorran mucho.

HTML
<button type="button" aria-haspopup="true" aria-expanded="false" id="menu-btn"> Archivo </button> <ul role="menu" aria-labelledby="menu-btn"> <li role="none"><button type="button" role="menuitem">Abrir</button></li> <li role="none"><button type="button" role="menuitem">Guardar</button></li> </ul>

Estática No interactiva, distribución uniforme

Grid role="grid"
role="grid"
Interactuar con filas o columnas
role="treegrid"

Tabs

Alternan entre vistas relacionadas dentro de un mismo contexto, sin cambiar de página — tres roles trabajan juntos para que el lector de pantalla entienda la relación.

01

Roles y estado activo

✕ Evitar
Vista general de la cuenta.
Información completa de la orden.
Actividad reciente registrada.
funciona al click, pero sin roles ni relación programática
✓ Preferir
Vista general de la cuenta.
Información completa de la orden.
Actividad reciente registrada.
✓

ARIA: role="tablist" en el contenedor, role="tab" en cada pestaña, role="tabpanel" en el contenido. aria-selected="true|false" marca la activa; aria-controls vincula cada tab con su panel. Prueben las dos: la de "Evitar" también cambia de panel al click — la diferencia no se ve, se escucha con un lector de pantalla.

HTML
<div role="tablist" aria-label="Secciones"> <button role="tab" aria-selected="true" aria-controls="panel-resumen" id="tab-resumen"> Resumen </button> <button role="tab" aria-selected="false" tabindex="-1" aria-controls="panel-detalle" id="tab-detalle"> Detalle </button> </div> <div role="tabpanel" id="panel-resumen" aria-labelledby="tab-resumen"> Vista general de la cuenta. </div> <div role="tabpanel" id="panel-detalle" aria-labelledby="tab-detalle" hidden> Información completa de la orden. </div> <script> // Click: activa el tab, actualiza aria-selected, muestra su panel. // Flechas ←/→, Home/End: mueven el foco entre tabs (roving tabindex). </script>

Accordions

Muestran u ocultan secciones de contenido. HTML tiene un elemento nativo que resuelve esto sin una línea de JavaScript.

01

Nativo vs. personalizado con ARIA

✓ Nativo
Sección 1 ▶
<details><summary> — sin JS, foco y teclado gratis del navegador.
Sección 2 ▶
Contenido de la sección 2 — se muestra al expandir.
✓
✓ Personalizado
aria-expanded + aria-controls a mano.
Contenido de la sección 2 — se muestra al expandir.
✓

Principio: no reinventar la rueda (otra vez) — si <details>/<summary> cubre el caso, no hace falta reconstruir foco, teclado y ARIA a mano. Reservar lo personalizado para cuando el diseño realmente lo exija.

HTML
<!-- Nativo — sin JS --> <details> <summary>Sección 1</summary> <p>Contenido de la sección.</p> </details> <!-- Personalizado — con ARIA a mano --> <button type="button" aria-expanded="true" aria-controls="panel-1" id="acc-1"> Sección 1 </button> <div id="panel-1" role="region" aria-labelledby="acc-1"> Contenido de la sección. </div>

Ejercicio: menú dropdown accesible

Construyan desde cero un menú dropdown accesible — este es el patrón que combina más de lo visto hoy en un solo componente.

  1. Creen un <button> con aria-haspopup y aria-expanded
  2. Creen una lista <ul role="menu"> con <li role="menuitem">
  3. Implementen navegación por flechas (↑↓) entre ítems
  4. Implementen Esc para cerrar y devolver el foco al botón
  5. Implementen Home/End para ir al primer/último ítem
  6. Verifiquen con Tab que el foco no se escape del menú mientras está abierto

Lo que no vimos hoy

Nueve patrones ya es mucho para una sesión. Estos quedan afuera por tiempo, no por importancia — reconozcanlos cuando aparezcan en v0.

Overlays

  • DrawersPanel lateral para detalle o edición sin perder contexto
  • TooltipsAclaración breve al pasar o enfocar un elemento
  • Menú contextualAcciones específicas de un elemento, al click derecho o long-press

Estado y feedback

  • Empty statesQué mostrar cuando todavía no hay datos
  • Skeleton / loadingAnticipar la forma del contenido mientras carga
  • Progress indicatorsBarra o círculo para procesos largos o de varios pasos

Entrada de datos

  • Forms & validaciónErrores en el momento, no solo al enviar
  • Date pickerElegir fechas sin depender de formato de texto libre
  • SearchAutocompletar y resultados incrementales
